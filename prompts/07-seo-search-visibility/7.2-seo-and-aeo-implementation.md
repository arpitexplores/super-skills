Implement the SEO and AEO improvements approved for this website. Support new and existing projects with any capable coding assistant. Optimise for Google, Bing, other search engines and AI answer systems without treating one platform as the sole authority. Approved project rules and later user decisions take precedence. Under this library's standing policy, /llms.txt, site FAQ coverage with matching FAQPage markup and keyword-density checks remain required SEO/AEO baseline components. Do not downgrade them to optional solely because a particular search platform does not use them. Preserve existing functionality, styling, routes, forms, integrations and business logic.

Confirm scope
Inspect the project, prior SEO audit, approved findings and existing SEO setup. Link work to approved issue IDs or explicit instructions. If audit findings or approval are missing, help prepare evidence and seek approval; do not implement speculative changes. For a new site, implement approved prelaunch work without claiming live indexing has been checked. Reuse existing documentation, brand rules and validation systems rather than create duplicates.

Plan safe changes
Identify affected pages, route templates, metadata sources, content integrations and deployment boundaries. Use framework-native metadata, sitemap, router and server capabilities when suitable. Avoid unnecessary packages and second SEO systems. Record risks, dependencies and rollback for redirects, canonicals, indexability or domain changes. Ask before changing important architecture, permissions or approved standards.

Production versus staging
Use the approved production origin for canonicals, structured data, sitemaps, social URLs and links. Keep localhost and staging URLs out of production output. Handle HTTPS, hostnames, slashes, parameters and redirects without loops. Development, staging, test and preview environments must not be indexed. Prefer authentication or network restrictions for sensitive sites. Public review previews are permitted when intentional, with reliable noindex headers or HTML, exclusion from production links and sitemaps, and suitable bot or access controls. Public access cannot guarantee blocking all crawlers; disclose residual risk. robots disallow alone cannot ensure deindexing and may prevent seeing noindex. Test without blocking production or authorised reviewers. Report required CDN, DNS or hosting changes, not unsafe workarounds.

Approved technical SEO
Implement relevant approved changes to HTTP statuses, redirects, canonicals, indexing, robots, X-Robots-Tag, crawlable navigation, internal links, semantics, images, performance, international and local SEO or ecommerce. Preserve CMS, API, database and spreadsheet integrations and dynamic data. Do not hardcode changing business information to simplify metadata. For missing routes, create a useful, accessible, branded 404 page with navigation and a real HTTP 404 status. Redirect only when a genuine replacement exists; avoid soft 404s.

Metadata and social cards
Use natural, distinct page titles and accurate descriptions aligned with brand voice. Page Topic | Brand is a possible convention, not mandatory. Implement appropriate page-specific Open Graph, X or Twitter Card and canonical metadata. Use real product or article images where available and an approved default sharing image for general pages, with valid production URLs.

Schema and FAQs
Implement accurate structured data based on real content. Consider Organization, WebSite, BreadcrumbList, Product, Article, BlogPosting, LocalBusiness, FAQPage and other approved types. Maintain helpful site FAQ coverage and valid FAQPage markup matching visible answers. Include purpose-built, search-intent-informed FAQ sections on relevant approved pages even when no customer literally asked each question. Within authorised SEO implementation treat accurate matching FAQ schema as a required baseline, while seeking approval for material new public copy or claims. Do not promise a particular rich-result feature. Check supported enhancements before claiming a benefit. Answers must address genuine questions; do not invent authors, prices, availability, ratings, reviews, credentials or facts. Validate markup syntax and relevant feature rules where available.

Sitemap, robots and updates
Use the project's existing sitemap generation where possible. Include only intended canonical indexable production URLs, covering relevant static and dynamic pages. Exclude private, broken, redirected, noindex, staging and unnecessary parameter URLs. Use reliable lastmod values, never fabricated dates or meaningless changefreq and priority. Implement approved robots policy; it is not an access-control system. Add IndexNow or another suitable update notification only if approved and supported by existing content update events.

AI search access and required llms.txt
Apply approved bot and snippet policies, distinguishing search discovery, training and user-triggered retrieval where controls differ. Do not change access without approval. Maintain accurate /llms.txt linking to important public canonical pages, updating rather than duplicating the file. File presence, correct canonical references and upkeep remain mandatory site requirements across the supported search and AI ecosystem; preserve them even where one engine gives no special treatment. For unlaunched sites, prepare verified production information without placeholders, private content or staging URLs. Keep it current when content changes. Never promise citations or Google ranking effects.

Content changes need approval
Brand terminology, tone and positioning take priority over awkward keyword targeting. Only change visible copy, headings, titles, FAQ answers, descriptions, calls to action, anchor text or navigation labels that were approved in the audit or explicitly authorised later. Integrate approved keywords naturally. For approved pages, check primary and supporting term counts, approximate keyword density, natural placement and variants before and after changes. Improve topic coverage without forced repetition or an invented universal density target. Keep approved purpose-built FAQ content in the plan. Avoid stuffing, fake urgency, generic AI language and invented claims. Flag missing business facts or new subjective decisions instead of guessing. If existing Content Governance rules are present, use them without requiring another framework.

Links, HTML and media
Use crawlable links, useful anchors, headings, semantic landmarks and accessible controls. Give informative images concise, accurate, context-specific alt text, not keyword lists. Describe meaningful differences in product-gallery views or variants. Decorative or redundant images need alt="" rather than missing alt. Image-only links and buttons need an accessible name conveying destination or action; avoid repeating an existing label. Complex diagrams need brief alt text plus explanation or data elsewhere. Preserve language and brand terms. Never invent visual details not verified in the asset or trusted product data. Avoid blanket alt generation from filenames, product names or generic templates. Reuse CMS/component fields and check that dynamic alt values remain accurate. Keep important images discoverable with relevant surrounding context and appropriate HTML elements; do not disturb existing design or layout.

Conditional site features
For ecommerce, implement approved product and variant schema, real offers, pricing, currency, availability, identifiers, collections, merchant feeds and faceted URL handling while retaining live data. For local businesses, use verified location, listing and service information. For multilingual sites, implement locale routes, canonical relationships and reciprocal hreflang. Skip irrelevant modules.

Tests and verification
Run relevant local lint, type checks, builds, tests and SEO validators yourself; do not require GitHub Actions or hosted gates. Verify applicable home, landing, category, product, article, missing-item and locale templates, comparing initial with rendered HTML where possible. Check important content and navigation in server-returned HTML and rendered output. Verify permitted search bots are not unintentionally excluded by robots, response headers, CDN protection or routing; preserve separately approved training and user-triggered crawler policies. Check titles, canonicals, social URLs, schema, redirects, robots, sitemap, llms.txt, staging isolation and alt text across dynamic galleries, decorative and linked images. Confirm forms, navigation, images and integrations work. Distinguish local from deployed evidence; never claim an unrun check passed.

Release and final report
Do not deploy or change DNS, CDN, hosting, Search Console, Bing Webmaster, Merchant Center or other external settings without approval. Report the approved issue IDs addressed, files and routes changed, tests and actual results, unresolved risks, rollback or external steps and post-deployment checks. Recommend monitoring search visibility, indexing, relevant AI citations and conversions where data is available. Compare available pre- and post-change technical evidence with Google generative AI reports, Bing AI Performance, relevant referrals and qualified outcomes when accessible. Record time windows and limits; do not attribute later traffic or citation changes automatically to one fix. SEO improvements do not guarantee rankings or citations. Stop and seek approval for any material change beyond the approved scope.
